# 07 · 技术路线图（能到哪、怎么到）

> 先说边界，再说野心。
> 这台车是**桌面级实验平台**：载荷几百克、没有机械臂、爬不了楼梯。
> 它的价值不是"当管家"，是让你把具身智能的全链路**亲手走一遍**，这套经验可以平移到任何机器人项目。

---

## 一、能力四层（按实现顺序）

### 第 1 层 · 遥控（Week 1-2）

- 手机 App 虚拟摇杆 / 电脑键盘 / 手柄（Xbox 连 iPhone）
- App 里能看到：画面、速度（无编码器时为 0）、电量（无分压时为空）
- 本质：一台"手机驱动的高性能遥控车"——只是起点

### 第 2 层 · 视觉闭环（Week 3-4，项目本体）

| 能力 | 原理 | 训练成本 |
|---|---|---|
| **人物跟随** | 目标检测出"人"的框 → 框心与画面中心的偏差 → PID 算转向/油门 | 零训练（用预训练模型） |
| **任意物体追踪** | 同上，换类别（80 类 COCO） | 零训练 |
| **端到端自动驾驶** | 输入整幅画面 → 输出左右轮速度；行为克隆（Behavior Cloning） | 采集 20-60 分钟 + 训练 0.5-2 小时 |

**第 2 层的价值**：走完 `采集 → 清洗 → 训练 → 量化 → 部署 → 验收` 这条闭环。这就是工业界做端侧 AI 的全流程，只是规模缩小 1000 倍。

```
iPhone 摄像头 1280×720
  ↓ resize 300×300
MobileNetV3-SSD / 自训的 YOLOv8n（TFLite）
  ↓ 目标框 [x,y,w,h] + 类别 + 置信度
控制器：框心偏差 → (转向, 油门)     ← 经典控制，不是神经网络
  ↓ BLE 0x0F 帧（左右轮 -255…255）
ESP32 → MX1508 → 电机
```

### 第 3 层 · 全设备接入（Week 5+，独一份的组合技）

| 设备 | 角色 | 实现要点 |
|---|---|---|
| **Action 5 Pro** | 摄影师 + 高质量训练数据源 | 磁吸车头出片；录的视频离线喂训练（不需要实时流） |
| **AirPods Pro 2** | 头部姿态遥控 | `CMHeadphoneMotionManager` 读 pitch/roll/yaw → 手势映射 → HTTP/WS 给 Mac → 转发控制 |
| **Siri** | 语音指挥 | 快捷指令 + SSH/webhook，10 分钟配好，零开发 |
| **TP-Link 摄像头** | 上帝视角 | 俯拍全场，对照"它看到的"和"它实际做的" |
| **旧显示器** | 训练监控屏 | 实时画面 + loss 曲线 + 状态 |

到这一步的演示视频是"头部开车、语音下指令、Action 出片、Mac 指挥"——**组合本身就稀缺**。

### 第 4 层 · 改代码的自由（完全开源）

- 换模型：训一个"只认我家猫"的检测器（300 张标注照片 + YOLOv8n，半天）
- 换任务：手势控制（MediaPipe Hands）、骨架跟随（YOLOv8n-pose）、找东西（接第 3 层）
- 改 App 源码：接 UVC 外接相机、加自定义 UI、加新的控制模式
- 换大脑：树莓派 5 / Jetson Orin Nano 替代手机，跑分割/大模型/SLAM

## 二、视觉 + 深度学习五层（怎么把 DL 真正融进去）

> 关键认知：**OpenBot 本身就是个视觉 DL 项目**。你不需要"把 DL 塞进去"，而是"接住它已有的管线，一层层往上换零件"。

### L1 · 走通官方训练链路（入门必做）

| 步骤 | 干什么 | 在哪 |
|---|---|---|
| 采集 | App 开数据采集模式，手柄开 20-30 分钟，画面 + 操作带时间戳 | iPhone |
| 清洗 | 删停车/抖动废帧，按 8:1:1 切训练/验证/测试 | Mac |
| 训练 | `policy/train.py`，PyTorch + MPS 后端 | Mac，0.5-2 小时 |
| 量化 | float32 → **int8** → `.tflite`（体积 1/4、速度 2×、精度掉 1-2%） | Mac |
| 部署 | ⚠️ iOS 要**重新编译 App**，把 `.tflite` 换进 Xcode 资源目录 | Mac + Xcode |
| 验收 | 同一段赛道训练前后各跑 3 次，比"跑完全程几次/撞几次/平均速度" | 客厅 |

### L2 · 换模型、换任务

| 路线 | 做法 | 取舍 |
|---|---|---|
| **TFLite**（官方路线） | Ultralytics 导出 `format=tflite int8=True` | 改动最小；但 iOS 上走 CPU/GPU，**吃不到 ANE** |
| **Core ML** | `coremltools` 转 `.mlpackage`，Swift 里用 Vision 调 | **直吃 A18 的神经网络引擎**，同模型快 2-3 倍、省电；代价是改约 100 行 Swift |

建议：先用 TFLite 跑通，再切 Core ML 做性能优化——这正好是"改 iOS 源码"的练手项目。

### L3 · 视觉 + 语言（VLA 的轻量版）

```
慢系统（Mac，VLM：Qwen2.5-VL-3B/7B 或调 API）
   ↑ 你说"去客厅看看有没有快递"
   ↓ 拆成：目标=快递盒 / 区域=客厅 / 动作序列=[前进, 扫描, 靠近]
快系统（iPhone，30 FPS 小检测模型 + 控制环）
   执行：检测 + 居中 + 避障，实时闭环
```

这就是学术界的**快慢双系统（System 1 / System 2）**：大模型聪明但慢（几百 ms 到几秒），小模型笨但快（30 ms）。在自己家里把它跑通，比看十篇论文实在。

工程连接：Mac 起 WebSocket 服务 → iPhone 端（改 OpenBot 源码）订阅高层指令，本地小模型负责执行。

### L4 · 多传感器融合

| 传感器 | 提供什么 | 备注 |
|---|---|---|
| **iPhone 的 ARKit（VIO）** | ⭐ 6DoF 位姿，**免费的视觉惯性里程计** | 最被低估，比编码器精度高 |
| 编码器（后补） | 轮速 / 里程 | 打滑时视觉准，暗处编码器准 |
| AirPods 头部姿态 | 人的朝向 | "人转头看哪，车就转向哪" |
| 单目深度（Depth Anything V2 small） | 相对深度图 | 替代超声波：知道"前方 0.8 米有障碍" |

融合算法：**EKF**（扩展卡尔曼滤波），ROS 的 `robot_localization` 有现成实现。做到这层，车就从"看到什么做什么"变成"知道自己在哪、在往哪走"。

### L5 · 换大脑（想跑大模型时的唯一出路）

| 平台 | 能跑什么 | 成本 |
|---|---|---|
| 手机（现状） | 3-5M 参数级检测网络 | 已有 |
| **树莓派 5 + Hailo-8L** | YOLOv8s 实时、功耗低 | ¥700+ |
| **Jetson Orin Nano Super** | 7B 级 VLM、ROS2 全家桶 | ¥2000+ |
| 相机换 Action 5 Pro（UVC） | 画质/动态范围吊打手机 | 已有 |

手机这时退居"显示屏 + 输入设备"。**这条路要等前四层走完再考虑**，否则就是拿钱换一堆跑不起来的代码。

## 三、三个必须提前知道的物理限制

| 限制 | 表现 | 对策 |
|---|---|---|
| **热降频** | A18 跑满 15 分钟发烫，帧率 30→15，「模型突然变笨」 | 降分辨率、限帧率、别在太阳下玩 |
| **BLE 延迟 20-50ms** | 高频闭环会抖 | 控制频率压在 10-20 Hz，决策交给视觉 |
| **数据质量 > 模型大小** | 20 分钟随意数据 < 1 小时平稳数据 | 换模型前先问：数据够不够 |

## 四、四周节奏（每个周末一个可验收成果）

| 周 | 目标 | 验收标准 | 耗时 |
|---|---|---|---|
| W0（工作日） | 采购 + 环境预热 | ESP32 能被 Mac 识别、固件编译通过 | 1 h |
| W1 | 机械 + 通电 | 架空状态下四轮方向正确 | 3-4 h |
| W2 | BLE + iOS App | 手机连上 `OpenBotCar`、能遥控 | 4-6 h（签名/Firebase 是大头） |
| W3 | 人物跟随 | 稳定跟人走 30 秒以上 | 3 h |
| W4 | 训练自己的策略 | 端到端跑完一圈不撞 | 1 周末 + 训练 |
