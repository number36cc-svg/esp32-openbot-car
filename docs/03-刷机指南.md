# 03 · 刷机指南（从零到"车会动"）

> 环境：macOS（Apple 芯片）· arduino-cli 1.5.2 · esp32:esp32 **2.0.17** · esptool 5.6.0
> 全程约 20 分钟，其中工具链下载占 15 分钟（约 1GB）。

## 0. 前置认知

| 事实 | 影响 |
|---|---|
| 板载串口是 **CH340** | macOS 免驱，插上就有 `/dev/cu.usbserial-*` |
| 高速波特率会失败 | 备份/烧录统一用 **230400** |
| ESP32 有 4MB Flash，app 分区 1.25MB | OpenBot 固件 1.08MB，够用但没富余 |
| 电池与 USB 不能同时供电 | 烧录前关电池开关 |

## 1. 安装工具链

### 1.1 arduino-cli（官方二进制）

```bash
mkdir -p tools && cd tools
curl -fL -o arduino-cli.tar.gz \
  https://downloads.arduino.cc/arduino-cli/arduino-cli_latest_macOS_ARM64.tar.gz
tar xzf arduino-cli.tar.gz
./arduino-cli version     # 期望 1.5.x
cd ..
```

> 为什么不 `brew install arduino-cli`：本机安全策略会拦 brew 的写入操作（`brew` 命令在收尾阶段被中断，包没装上）。官方二进制下载到项目目录里更稳，也方便随项目一起丢弃。

### 1.2 ESP32 核心（1GB，耐心等）

```bash
export ARDUINO_DIRECTORIES_DATA="$PWD/arduino-data"
export ARDUINO_DIRECTORIES_DOWNLOADS="$PWD/arduino-dl"
export ARDUINO_DIRECTORIES_USER="$PWD/arduino-user"

./tools/arduino-cli config init --overwrite
./tools/arduino-cli config set board_manager.additional_urls \
  https://espressif.github.io/arduino-esp32/package_esp32_index.json
./tools/arduino-cli core update-index
./tools/arduino-cli core install esp32:esp32@2.0.17
```

**版本为什么锁 2.0.17**：OpenBot 官方 CI 用的就是这个版本。用 3.x 有 API 变更（LEDC/`ledcSetup` 弃用）会编译报错。

也可以直接跑仓库里的脚本：`./scripts/setup-toolchain.sh`。

### 1.3 esptool

```bash
brew install esptool     # 或 pip3 install esptool
esptool version
```

## 2. 备份原厂固件（**动手前第一件事**）

```bash
esptool --port /dev/cu.usbserial-10 --baud 230400 \
  read-flash 0 0x400000 firmware-backup/original-firmware-4MB.bin
```

- 4MB 全片读取，本机耗时约 **3 分 12 秒**（174 kbit/s）
- 用途：卖家原厂是"WiFi 网页遥控"固件，哪天想玩回去，一条命令就恢复
- 也可以 `./scripts/ob.sh backup`

## 3. 编译

```bash
./scripts/build.sh
```

期望输出（tail）：

```
Sketch uses 1128017 bytes (86%) of program storage space. Maximum is 1310720 bytes.
Global variables use ... bytes ... leaving ... bytes for local variables.
--- 产物 ---
openbot.ino.bin  openbot.ino.bootloader.bin  openbot.ino.partitions.bin
```

> **86% 是个警戒线**。想加功能（OLED、超声波、额外日志）要先算体积，超过 100% 就烧不进去，得改分区表。

## 4. 烧录

```bash
esptool --port /dev/cu.usbserial-10 --baud 230400 \
  --before default-reset --after hard-reset \
  write-flash --flash-mode dio --flash-freq 40m --flash-size 4MB \
  0x1000 firmware/build/openbot.ino.bootloader.bin \
  0x8000 firmware/build/openbot.ino.partitions.bin \
  0x10000 firmware/build/openbot.ino.bin
```

成功标志：

```
Wrote 1128017 bytes ... 
Verifying written data...
Hash of data verified.
Hard resetting via RTS pin...
```

### 为什么不用 `arduino-cli upload`

`arduino-cli upload` 默认用 921600 波特率，在 CH340 上**必然失败**：

```
A fatal error occurred: Failed to write to target Flash after seq ...
```

而 `arduino-cli upload` 不方便指定波特率。所以统一用 esptool 手动烧，参数可控。

## 5. 看日志

```bash
./scripts/ob.sh monitor     # arduino-cli monitor，115200
```

**前提**：固件 `#define DEBUG 1`。本仓库的固件已经打开（`openbot.ino` 第 55 行）。

> 现象：烧完固件读串口一片空白 → 大概率是 `DEBUG 0`，固件根本不打印任何东西。不是板子坏了。

## 6. 验证成功的两条独立证据

| 证据 | 方法 | 说明 |
|---|---|---|
| 串口 | `./scripts/ob.sh monitor` 看到启动日志/状态 | 说明固件在跑 |
| BLE 广播 | iPhone 装 **nRF Connect**，扫到 **`OpenBotCar`** | 说明蓝牙协议栈正常 |

BLE 广播里应能看到：

- 设备名 `OpenBotCar`
- 服务 UUID `61653DC3-4021-4D1E-BA83-8B4EEC61D613`
- 广播间隔约 40ms

## 7. 恢复原厂固件

```bash
./scripts/ob.sh restore     # 烧回 4MB 整片镜像（0x0 起始）
```

也可以只烧我们的方向测试固件（见 [05-固件适配说明](05-固件适配说明.md)），不用整片恢复。

## 8. 常见报错对照

| 报错 | 原因 | 处理 |
|---|---|---|
| `Failed to connect to ESP32: Timed out waiting for packet header` | 没用数据线 / 驱动没起来 / 板子没进下载模式 | 换线；拔插 USB；按住 BOOT 再插 |
| `Failed to write to target Flash after seq N` | 波特率太高 | 降到 **230400**（甚至 115200） |
| `A fatal error occurred: MD5 of file does not match data in flash!` | 烧录中断/供电不稳 | 重烧；确认电池开关已关 |
| `zsh: parse error near ')'` | 整块粘贴带 `#` 注释的脚本到 zsh 交互模式 | 去掉注释，或保存成 `.sh` 再跑 |
| 编译报 `ledcSetup was not declared` | ESP32 核心用了 3.x | 装回 2.0.17 |
| 端口不存在 | CH340 未被识别 | `ls /dev/cu.*`；换 USB 口；换数据线 |

## 9. 一条铁律

> **插 USB 烧录 → 关电池开关；拔 USB 跑车 → 开电池开关。两者永不同时在线。**

USB 的 5V 和板载 3.3V 同时供给 ESP32，轻则烧录失败（供电竞争导致复位），重则伤板。这不需要拆电池，拨一下开关就行。
